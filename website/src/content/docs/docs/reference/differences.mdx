NeoSkript's spec is Skript 2.17.0's behaviour, messages included. Skript's whole test suite passes on it (862 of 862 on Paper), and every one of the differential harness's 1,613 units, each example in Skript's documentation and NeoSkript's own probes, prints the same messages and saves the same `variables.csv` as a real Skript server.

What's on this page is what's left: the deliberate differences, what NeoSkript adds, and what it doesn't have yet.

## Deliberate differences

- **A reload with errors keeps the running version.** Skript unloads a script before loading it again; NeoSkript compiles first, and keeps the version that's running if the new one has errors. See [reloading](/docs/server/reloading/).
- **It won't start next to Skript.** The two would fight over the same scripts and `/skript` command.
- **Its own folder.** Scripts and variables live in `plugins/NeoSkript`, copied from `plugins/Skript` on the first start.
- **`config.yml`, not `config.sk`,** with Skript's settings that change how scripts behave, copied from `config.sk` on the first start. See [configuration](/docs/server/configuration/).
- **Folia.** Skript doesn't run on Folia; NeoSkript runs on its region threads. See [Folia](/docs/server/folia/).
- **`/sk reload aliases`** also reloads the scripts that use the aliases that changed, and those that had errors. Skript only reads the alias files again, so scripts keep the items they loaded with until they're reloaded.
- **`/sk update`** uses NeoSkript's [update checker](/docs/server/updates-and-metrics/), and **`/sk gen-docs`** points to the [syntax reference](/syntax/) instead of writing docs files.
- **`/sk`'s messages are NeoSkript's own**, in the [theme](/docs/server/configuration/#make-it-look-like-your-server) from `config.yml`, with reload reports per script. Problems at startup and runtime errors keep Skript's look.

## Skript bugs NeoSkript fixes

Where Skript 2.17 has a bug, NeoSkript does what Skript meant rather than copy it:

- **Script folders in `/sk`:** Skript 2.17 never finds folders given to `/sk reload`, `enable` or `disable`, because of a bug. NeoSkript finds them; a name ending in `/` is a folder.
- **Warning frames:** Skript 2.17's runtime warning frames never reset. NeoSkript resets them as intended.
- **Numbers copied from `config.sk` that could stall the server:** a `number accuracy` beyond 1000 either way is copied as 1000 or -1000, and a `maximum target block distance` above 1000 as 1000, as tracing that far or writing every number with that many digits can stall a server. A negative distance, which Skript's `target`, `targeted block` and `blocks in front of` each read differently, is copied as 0. At 0, `targeted block` (not `actual targeted block`) looks 1 block: Bukkit's line of sight never ends at 0.
- **`case sensitive` in `positions of`:** Skript 2.17 has its option the wrong way round there: off, `all positions of "a" in "Abca"` heeds case (4), and on, it doesn't (1 and 4). NeoSkript follows the option, like the rest of Skript's text syntax.
- **Comparisons of words:** `projectile is an arrow` was false because of how words were read. NeoSkript reads words in comparisons as Skript's `CondCompare` means to, so it's true.
- **Alias files that stop Skript loading aliases:** in Skript 2.17, an alias starting with `{`, a block state without `=` (`[facing]`), components the server can't read, a `minecraft version` that isn't a version, or a lone `}` in a name stop it loading any aliases, and can disable it. NeoSkript reports an error for the line and loads the rest.
- **Alias names with capitals:** Skript keeps `Ruby = minecraft:red_dye` as written but looks names up in lower case, so it never finds it. NeoSkript finds it, and writes the item as `Ruby`.

## What NeoSkript adds

- <Badge text="NeoSkript only" variant="tip" /> `run on <entity or location>:` runs code on the thread that owns something, for Folia. On Paper it just runs. Scripts that use it don't load on Skript.
- `neoskript-cli`, the [script checker](/docs/cli/), and NeoSkript's parser in [the browser](/parser/) and [code editors](/docs/editors/).

## Not there yet

- **Skript addons** (SkBee, skript-yaml, SkQuery, skript-reflect and others) don't load. A compatibility layer is planned after 1.0. See [addons](/docs/addons/).
- **Databases for variables**: Skript's SQLite and MySQL storage. Skript 2.17 only supports CSV out of the box. Planned after 1.0.

## Known differences

These are the differences the test harness knows about, from `known-differences.txt` and the progress log:

- **One unit varies in Skript itself.** `ExprLocationAt-1`'s error message depends on the order Skript sorts its syntax in, which changes from run to run. NeoSkript gives one of Skript's two results.
- **Folia's global thread can't read the world.** The differential's `world` probe reads blocks from the console, which on Folia runs on the global thread, where reading regions isn't allowed.
- **Skript's suite on Folia: 860 of 862.** The two left read a chest at the spawn of a random world from the test's region. Folia only allows that from the chest's own region.
- **`permission message:`** is deprecated in Skript 2.17, and gives the same warning on NeoSkript.
- **The `prefix:` command entry** is read, but commands are always registered under the `skript:` namespace.
- **`use type properties: false`** gives Skript's syntax from before 2.13, with a few gaps. Item words written straight into it (`name of diamond`, `amount of 3 diamonds`) and `size of chest inventory` aren't read as Skript reads them, nor is `x of location(1, 2, 3)`. `name of "hello"` is none rather than an error, and a few lines that are errors on both, such as `title of "hello"`, `5 is empty` and `{_list::*} is empty`, give other messages, as does `{_list::*} and "x" is empty` (Skript says variables can't be used there). `set name of random element of all players` isn't refused when the script loads, as Skript refuses a player's name: NeoSkript knows the values are players only when it runs, where setting the name does nothing. Items, slots and locations in variables work as in Skript.
- **`on load` at startup runs on the first tick.** Skript runs it while it loads the scripts. In a script with an `on load`, the triggers below it (and in scripts after it) start listening when it runs, so an event in the moment between the scripts loading and the first tick doesn't reach them; on Skript they weren't registered yet then either. `/sk reload` and `auto reload` run `on load` straight away, as Skript does.
