NeoSkript's settings are in `plugins/NeoSkript/config.yml`. It's written on the first start, with a comment on every setting. NeoSkript has no `config.sk`: Skript's settings for text, some syntax, the language, logging, warnings, hooks, events, runtime errors, effect commands and player variables are here, with Skript's defaults, and moving over copies the ones you changed. Those that don't apply to NeoSkript, or aren't here yet, are [listed](#skript-settings-that-dont-apply).

Apply changes with `/sk reload config`. Most settings apply at once; [some wait for a restart](#what-applies-when).

- A setting that isn't valid falls back to its default, and the console says which and why.
- A file that isn't valid YAML is never overwritten: on a reload the running settings stay, and at startup NeoSkript runs on the defaults until it's fixed.
- A file NeoSkript can read but not write, such as a read-only mount, is used as it is; the console says what it couldn't add.

## Make it look like your server

The `theme` section at the top sets the look of NeoSkript's messages: `/sk`, reload reports and update notices. It's the same as in Xena Studios' other plugins: a prefix, the text colour, and three styles the messages use as tags.

```yaml
theme:
  prefix: "<dark_gray>[<#FF4D9D>NeoSkript</#FF4D9D>]</dark_gray> "
  base: "<gray>"            # text with no tag of its own
  highlight: "<#FF4D9D>"    # names and numbers
  success: "<#5EE08A>"      # done
  error: "<#FF6B6B>"        # something went wrong
```

| Setting | Default | What it styles |
|---|---|---|
| `theme.prefix` | `<dark_gray>[<#FF4D9D>NeoSkript</#FF4D9D>]</dark_gray> ` | The start of each message. `""` for none. |
| `theme.base` | `<gray>` | Message text with no tag of its own. |
| `theme.highlight` | `<#FF4D9D>` | Names and values, such as a script or a number. |
| `theme.success` | `<#5EE08A>` | Something done, such as a script reloaded. |
| `theme.error` | `<#FF6B6B>` | Something that went wrong, such as a script's errors. |

Styles are [MiniMessage](https://docs.advntr.dev/minimessage/format) tags, such as `<gray>`, `<#FF4D9D>` or `<gold><bold>`. Quote a colour that starts with `#`. The prefix can be anything, gradients too, or `""` for none. It's the only setting that may be empty; any other left empty falls back to its default.

Script problems at startup and runtime errors keep Skript's look, since tools and guides read them.

## What applies when

`/sk reload config` applies these at once:

- the theme;
- `update-checker`;
- `language`, `text`, `syntax`, `verbosity` and `warnings`;
- `variables.player-uuids-in-names`, `variables.player-variable-fix`, `variables.compress-backups` and `variables.save-interval`;
- the `runtime-errors` limits;
- `effect-commands`.

`text.case-sensitive` applies at once to comparisons and `contains`; replace and split read it when a script loads, as in Skript, so reload the scripts too. The same goes for `warnings`: they're given when scripts load.

`metrics`, `databases`, `variables.recover`, `hooks` and the `events` settings apply when the server restarts. The reload says so when one of them changed.

`aliases.load-defaults` applies on `/sk reload aliases`, which reads it from `config.yml` itself, on `/sk reload all`, or on restart.

## config-version

| Setting | Default | What it does |
|---|---|---|
| `config-version` | `3` | Managed by NeoSkript, to carry your settings forward on updates. Don't edit it. |

See [updating NeoSkript](#updating-neoskript).

## metrics

| Setting | Default | What it does |
|---|---|---|
| `metrics` | `true` | Sends anonymous usage statistics to [bStats](https://bstats.org/plugin/bukkit/NeoSkript/34868). `false` turns it off. Applies on restart. |

bStats can also be turned off for every plugin at once in `plugins/bStats/config.yml`. See [updates and bStats](/docs/server/updates-and-metrics/).

## update-checker

| Setting | Default | What it does |
|---|---|---|
| `update-checker` | `true` | Checks Modrinth for newer NeoSkript versions when the server starts and once a day. `false` turns it off. |

See [updates and bStats](/docs/server/updates-and-metrics/) for who hears about a new version.

## aliases

| Setting | Default | What it does |
|---|---|---|
| `aliases.load-defaults` | `true` | Loads Skript's default aliases, such as `speed potion` or `flight 1 firework rocket`. Skript's `load default aliases`. With `false`, items are named only by the alias files in `plugins/NeoSkript/aliases` and after their Minecraft ids (`red dye`). |

Moving over from Skript copies Skript's `load default aliases`. See [custom aliases](/docs/scripts/items/#custom-aliases) for the alias files.

## language

| Setting | Default | What it does |
|---|---|---|
| `language` | `english` | The language of the messages scripts show from Skript's language files. Skript's `language`. |

Skript's language files are built in: `english`, `german`, `french`, `spanish`, `dutch`, `polish`, `russian`, `turkish`, `catalan`, `japanese`, `korean` and `simplifiedchinese`. A `<name>.lang` file in `plugins/NeoSkript/lang`, in Skript's format, adds a language or changes some of one's messages, as `plugins/Skript/lang` does for Skript. Moving over copies that folder.

What scripts show from them is what nothing is in text (`<none>`, `<tanımsız>` in Turkish), a command's default cooldown message, and how a script's problems are reported when it loads (`Line 5: (shop.sk)`, `Satır 5` in Turkish). Skript's own messages for `/sk` and reloads don't apply: NeoSkript's are its own, in English. A language with no file falls back to English, with a warning.

## text

How scripts write and compare text. Skript's options of the same names.

| Setting | Default | What it does |
|---|---|---|
| `text.date-format` | `default` | How dates are written as text. `default` is the server locale's short date and time, as `1/15/24, 10:30 AM`, or write a [SimpleDateFormat](https://docs.oracle.com/javase/8/docs/api/java/text/SimpleDateFormat.html) pattern such as `yyyy-MM-dd HH:mm`. `log` stamps its lines with it too. Skript's `date format`. |
| `text.number-accuracy` | `2` | The most decimal places a number is written with, without trailing zeros: `1/3` is `0.33`. `0` or below rounds to whole numbers, and below `0` `numbers from 1.5 to 30` steps by 10s, as in Skript. From `-1000` to `1000`. Variable names always keep up to 8, as in Skript. Skript's `number accuracy`. |
| `text.case-sensitive` | `false` | Whether comparing texts, `contains`, replace, split, `positions of` and comparing text components heed case. Skript's `case sensitive`. |
| `text.color-codes-reset-formatting` | `true` | Whether a colour (`&a`, `<red>`) turns off bold, italics and the rest before it, as Minecraft's own codes do. Skript's `color codes reset formatting`. |
| `text.safe-tags` | `color`, `decorations`, `gradient`, `rainbow`, `reset`, `transition`, `pride`, `shadowColor` | The MiniMessage tags read in text that isn't the script's own, such as a player's chat message made `colored`. Tag names, or [groups](https://docs.advntr.dev/minimessage/format) of them. Skript's `safe tags`. |
| `text.parse-links` | `disabled` | Whether text that looks like a link is made clickable: `disabled`, `strict` (only `http://` and `https://` links) or `lenient` (anything with a dot, such as `example.com`). Skript's `parse links in chat messages`. |

Skript has its `case sensitive` option the wrong way round in `positions of "a" in "Abc"`: off, it finds text with case, and on, without. NeoSkript follows the option.

## syntax

Settings for particular syntax. Skript's options of the same names.

| Setting | Default | What it does |
|---|---|---|
| `syntax.target-block-distance` | `100` | How many blocks away `targeted block`, `target` and `blocks in front of` look, from 0 to 1000. Skript's `maximum target block distance`. |
| `syntax.player-name-pattern` | `[a-zA-Z0-9_]{1,16}` | The text that can be read as an offline player's name, as a Java regular expression. A UUID always can. Skript's `player name regex pattern`. |
| `syntax.legacy-tab-completion` | `true` | Whether other plugins can add tab completions to script commands, through Bukkit's `TabCompleteEvent`. Off, a script command's completions are only its own. Skript's `enable legacy tab completion event compatibility`. |

## verbosity

| Setting | Default | What it does |
|---|---|---|
| `verbosity` | `normal` | How much NeoSkript logs. Skript's `verbosity`. |

- `low`: not even how many scripts and variables loaded.
- `normal`: those, and problems.
- `high`: also how many structures each script has, and each plugin hooked into.
- `very high`: also each structure as it loads, and each event as it fires, with the triggers it runs and how long each took. Write it `very-high` or `"very high"`.
- `debug`: as `very high`. Skript also writes out every line it parses; NeoSkript doesn't.

Events are named by their class, as in Skript, and triggers by their script and line.

## warnings

Warnings scripts get when they load. Each is Skript's `disable ... warnings` turned round: `false` turns that warning off for every script. A script can still turn one off for itself, as in Skript.

| Setting | Default | The warning |
|---|---|---|
| `warnings.variable-not-saved` | `true` | A global variable set to a value that can't be saved, so it's lost when the server stops. Skript's `disable variable will not be saved warnings`. |
| `warnings.missing-and-or` | `true` | A list without `and` or `or`. Skript's `disable variable missing and/or warnings`. |
| `warnings.variable-starting-with-expression` | `true` | A variable's name starting with an expression, as in `{%player%::money}`. Skript's `disable starting a variable's name with an expression warnings`. |
| `warnings.single-colon-in-variable-name` | `true` | A single `:` in a variable's name, as in `{money:%player%}`. Skript's `disable single colon in variable name warnings`. |
| `warnings.unreachable-code` | `true` | Code after a `stop`, `return` or `exit`. Skript's `disable unreachable code warnings`. |
| `warnings.long-parse-time` | `2 seconds` | A line that takes longer than this to parse. `0 seconds` turns it off. Skript's `long parse time warning threshold`. |

## hooks

The plugins NeoSkript hooks into for their syntax, when they're installed. Each is Skript's `disable hooks` turned round: `false` leaves that plugin alone, so its syntax isn't there. Applies on restart.

| Setting | Default | Hook |
|---|---|---|
| `hooks.vault` | `true` | Vault: money, chat prefixes and suffixes, permission groups. Skript's `disable hooks.vault`. |
| `hooks.worldguard` | `true` | WorldGuard's regions. Skript's `disable hooks.regions.worldguard`. |
| `hooks.grief-prevention` | `true` | GriefPrevention's claims, as regions. Skript's `disable hooks.regions.grief prevention`. |

## variables

| Setting | Default | What it does |
|---|---|---|
| `variables.recover` | `false` | Native storage only: a one-shot recovery of a damaged `variables.nsv` that no snapshot can repair. Loads everything up to the last good save, turns itself off first, keeping the file's comments, then backs the damaged file up and lists what's lost. If config.yml can't be changed (read-only, or from a newer NeoSkript), it isn't used, and the console says so. Works with either storage. Applies on restart, and only does anything when the file is damaged. |
| `variables.save-interval` | `5 minutes` | How often changed variables are saved to `csv` and `native` databases, at least every 10 seconds. They're also saved when the server stops. SQL databases write changes within a second or so. |
| `variables.player-uuids-in-names` | `true` | Whether a player in a variable's name, as in `{money::%player%}`, is their UUID (`true`) or their name. Skript's `use player UUIDs in variable names`. |
| `variables.player-variable-fix` | `true` | A player kept in a variable who leaves and joins again is a new player to the server. On, reading the variable gives the player now online, and stores them. Off, it gives the old player, whom messages and changes no longer reach. Skript's `player variable fix`. |
| `variables.compress-backups` | `true` | Whether the backups each database makes every `backup-interval` are gzipped (`variables_<time>_scheduled.csv.gz`), at Skript's best compression. Compressing reads only the finished copy, so saves never wait for it. Skript's `compress backups`. |

Moving over from Skript copies Skript's `use player UUIDs in variable names` setting into `player-uuids-in-names`, so the variables Skript saved are found. See [variables and storage](/docs/server/variables/).

## databases

Where global variables are saved: Skript's `databases:` section from `config.sk`, with the same options. Each variable is saved in the first database, from the top, whose `pattern` matches its whole name. The default is one CSV database, `default`, for everything, backed up every 2 hours with the newest 12 kept. A server that moved from Skript gets its `config.sk` section instead, copied as is, backups included: with Skript's default config that's every 2 hours, keeping every backup. Applies on restart. See [databases](/docs/server/variables/#databases) for examples, sharing variables between servers, and what happens when a database is down.

```yaml
databases:
  default:
    type: "csv"
    pattern: ".*"
    file: "variables.csv"
    backup-interval: "2 hours"
    backups-to-keep: 12
```

| Setting | Default | What it does |
|---|---|---|
| `type` | | `csv` (Skript's `variables.csv`), `native` (NeoSkript's own [native storage](/docs/server/variables/#native-storage), in `variables.nsv` beside `file`), `sqlite`, `mysql`, or `disabled`. Skript's `file` and `flatfile` mean `csv`, and `none` means `disabled`. |
| `pattern` | | A [regular expression](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/regex/Pattern.html) the variable's whole name must match, such as `db_.*`. `.*` matches everything. |
| `file` | | `csv`, `native` and `sqlite`: the file, relative to `plugins/NeoSkript`, or a full path. An SQLite file always ends in `.db`, as in Skript. |
| `backup-interval` | `2 hours` | `csv`, `native` and `sqlite`: how often the file is copied to `backups/`, exactly as written, however short, as in Skript. `2 hours` in a new config and one carried forward from before the `databases` section; a server that moved from Skript has its `config.sk` value. `0` for never, and then nothing is removed either, whatever `backups-to-keep` says. Left out of a database, there are none, as when Skript's `config.sk` doesn't say. Under a tick (50 ms), such as `0 seconds`, none are made. |
| `backups-to-keep` | `12` | How many of the file's backups to keep, the oldest removed first. `12` (a day's worth) in a new config and one carried forward from before the `databases` section; a server that moved from Skript has its `config.sk` value. Left out of a database, `-1`. `-1` keeps them all; `0` makes none and removes the file's old ones when the server starts, as in Skript, unless `backup-interval` is `0`. |
| `monitor-changes` | `false` | `sqlite` and `mysql`: read other servers' changes from the database every `monitor-interval`, for servers that share it. |
| `monitor-interval` | `20 seconds` | How often, at least every second. |
| `merge-changes` | `true` | With `monitor-changes`: two servers' changes to one variable are merged where they can be, so additions on both count ([sharing variables](/docs/server/variables/#sharing-variables-between-servers)). `false` keeps Skript's rule exactly: the last write wins. |
| `host`, `port`, `user`, `password`, `database` | | `mysql`: where the database is. The password is never shown in the console or `/sk info`. |
| `table` | `variables21` | `sqlite` and `mysql`: the table, Skript's by default. |

Keys can be written as in `config.sk` too (`monitor changes`, `backup interval`), so a section can be pasted from Skript. A database whose settings can't be used, such as a missing `file`, an unknown `type`, or a file or MySQL table another database already uses, isn't used, and the console says why; it still owns its pattern, so its variables aren't saved in another database by mistake.

## events

| Setting | Default | What it does |
|---|---|---|
| `events.priority` | `high` | The priority scripts listen to events at: `lowest`, `low`, `normal`, `high`, `highest` or `monitor`. As in Skript, `high` lets scripts see what most other plugins did to an event, and still cancel it. Applies on restart. |
| `events.listen-to-cancelled` | `false` | Whether `on <event>` triggers also run for events another plugin cancelled. Applies on restart. |

## runtime-errors

Errors that happen while a script runs are collected over frames of time. Each frame prints up to a limit, and what wasn't printed is summed up at the end of the frame. These are Skript's `runtime errors` settings from `config.sk`, with the same defaults.

| Setting | Default | What it does |
|---|---|---|
| `frame-duration` | `1 second` | How long each frame is. |
| `total-errors-per-frame` | `8` | The most errors printed per frame. More are hidden, and counted at the end of the frame. |
| `errors-from-one-line-per-frame` | `2` | The most errors one line prints per frame, so a line in a loop can't fill the frame. |
| `error-spam-timeout-limit` | `4` | A line with this many errors in a frame is put in timeout: its errors are hidden for a while. |
| `error-timeout-length` | `10` | How many frames a line stays in timeout. |
| `total-warnings-per-frame` | `8` | The same as `total-errors-per-frame`, for runtime warnings. |
| `warnings-from-one-line-per-frame` | `2` | The same as `errors-from-one-line-per-frame`, for warnings. |
| `warning-spam-timeout-limit` | `4` | The same as `error-spam-timeout-limit`, for warnings. |
| `warning-timeout-length` | `10` | The same as `error-timeout-length`, for warnings. |

All of them are under `runtime-errors:`. A negative limit falls back to its default. Players with `skript.see_runtime_errors` are told in chat when errors happen; the details go to the console.

## effect-commands

| Setting | Default | What it does |
|---|---|---|
| `effect-commands.enabled` | `false` | Whether console commands and chat messages starting with the token run as effects. Skript's `enable effect commands`. |
| `effect-commands.token` | `"!"` | What an effect command starts with. It can be longer than a character, but shouldn't start with `/`. Skript's `effect command token`. |
| `effect-commands.allow-ops` | `false` | Whether ops can use effect commands without the `skript.effectcommands` permission. Skript's `allow ops to use effect commands`. |
| `effect-commands.log` | `false` | Whether players' effect commands are logged, as `<player> issued effect command: <command>`. Skript's `log effect commands`. |

These commands can do anything, so give the permission carefully. See [effect commands](/docs/server/effect-commands/).

## Moving from Skript

The first start copies these settings from Skript's `config.sk`, read as Skript reads it, so a server that changed one behaves as it did:

| Skript's `config.sk` | NeoSkript's `config.yml` |
|---|---|
| `language` | `language` |
| `load default aliases` | `aliases.load-defaults` |
| `date format` | `text.date-format` |
| `number accuracy` | `text.number-accuracy` |
| `case sensitive` | `text.case-sensitive` |
| `color codes reset formatting` | `text.color-codes-reset-formatting` |
| `safe tags` | `text.safe-tags` |
| `parse links in chat messages` | `text.parse-links` |
| `maximum target block distance` | `syntax.target-block-distance` |
| `player name regex pattern` | `syntax.player-name-pattern` |
| `use player UUIDs in variable names` | `variables.player-uuids-in-names` |
| `player variable fix` | `variables.player-variable-fix` |
| `plugin priority` | `events.priority` |
| `listen to cancelled events by default` | `events.listen-to-cancelled` |
| `enable legacy tab completion event compatibility` | `syntax.legacy-tab-completion` |
| `verbosity` | `verbosity` |
| `disable variable will not be saved warnings` | `warnings.variable-not-saved`, turned round |
| `disable variable missing and/or warnings` | `warnings.missing-and-or`, turned round |
| `disable starting a variable's name with an expression warnings` | `warnings.variable-starting-with-expression`, turned round |
| `disable single colon in variable name warnings` | `warnings.single-colon-in-variable-name`, turned round |
| `disable unreachable code warnings` | `warnings.unreachable-code`, turned round |
| `long parse time warning threshold` | `warnings.long-parse-time` |
| `disable hooks` (`vault`, `regions.worldguard`, `regions.grief prevention`) | `hooks`, turned round |
| `runtime errors` | `runtime-errors` |
| `compress backups` | `variables.compress-backups` |
| `databases`, with the files it names | `databases` |
| `enable effect commands`, `effect command token`, `allow ops to use effect commands`, `log effect commands` | `effect-commands` |

Values are read as Skript reads them: `yes` and `on` are true but `True` isn't, `1_000` is a number, and `Strict` isn't a link mode. A number accuracy beyond 1000 either way is copied as 1000 or -1000, and a target distance below 0 as 0 or above 1000 as 1000 (see [differences](/docs/reference/differences/)).

A setting `config.sk` doesn't have keeps NeoSkript's default, which is the value in Skript's default `config.sk`. One Skript can't read, such as `plugin priority: hihg`, is copied as what Skript then runs with: its built-in default (`normal` for the priority). The console lists what was copied, and any setting it found that doesn't apply, with why. See [moving from Skript](/docs/moving-from-skript/).

## Skript settings that don't apply

| Skript's `config.sk` | Why |
|---|---|
| `check for new version`, `update check interval`, `release channel` | NeoSkript checks Modrinth for its own versions instead: `update-checker`. |
| `enable timings` | Paper has had no Timings since 1.19.4, and on Paper Skript only warns that it can't turn them on. To see what scripts cost, use [spark](https://spark.lucko.me/), which is built into Paper. |
| `soft api exceptions` | It turns two failures Skript stops on into errors: alias files without an item Skript's own code needs (`type ... not found`), and Skript addons' mistakes registering types. NeoSkript names every Minecraft item after its id whatever the alias files have, and doesn't load Skript addons. |
| `disable hooks.regions.precious stones`, `disable hooks.regions.residence` | NeoSkript doesn't hook into PreciousStones or Residence. |
| `use type properties` | Not yet: with it off, Skript reads `name of`, `amount of` and the other type property syntax with its older versions, which NeoSkript doesn't have. NeoSkript reads scripts as with it on, Skript's default. Tracked in [#26](https://github.com/xena-studios/neoskript/issues/26). |
| `script loader thread size` | NeoSkript loads scripts its own way: each file is parsed in parallel, and nothing waits on the main thread. There's nothing to size. |
| `version` | Skript's own record of its config's version. NeoSkript's is `config-version`. |
| `case-insensitive variables` | Not here: NeoSkript's variable names always ignore case, as Skript's do by default. If `config.sk` turned it off, moving over says so, and names, as errors, the saved variables that differ only by case (`{coins::Bob}` and `{coins::bob}`), as NeoSkript keeps only one of each. Skript's `variables.csv` is left as it was. |
| `variable changes until save` | Skript writes each change to `variables.csv` as it happens, and rewrites the whole file once this many changes pile up. NeoSkript writes the changed variables every `variables.save-interval` instead (native storage appends only what changed), so there are no piled-up changes to count. Moving over says so when it isn't Skript's 1000. |
| `execute functions with missing parameters` | Not here: NeoSkript always runs a function whose argument has no value, as Skript does by default (`true`). With it off, Skript skips such a call and gives nothing. Moving over says so when `config.sk` turned it off. |
| `simplify syntax on parse` | Not here: NeoSkript always works out what it can while a script loads (`1 + 1` is `2`), as Skript does by default (`true`); Skript's own config doesn't list it. Moving over says so when `config.sk` turned it off. |
| `keep configs loaded` | It keeps each script's parsed file in memory for Skript addons that read it; NeoSkript doesn't load Skript addons. |
| `allow unsafe platforms` | It lets Skript start on a server platform it doesn't support. NeoSkript is built on Paper's API, for Paper and Folia only; there's no other platform to allow. |
| `updater download tries` | For Skript's own updater; NeoSkript's `update-checker` doesn't download. |
| `allow function calls before definations`, `enable script caching`, `addon safety checks`, `case-insensitive commands`, `keep command last usage dates` | They do nothing in Skript 2.17: deprecated or no longer read. |

## Updating NeoSkript

When a new version adds settings, NeoSkript adds them with their defaults and says so in the console.

When the layout changes, `config-version` goes up:

- The old file is backed up as `config.yml.bak-v<version>`.
- The new one keeps every value you set, and any keys that aren't NeoSkript's settings.
- Your comments on NeoSkript's settings are replaced by its own; the backup has them.

Files without `config-version` or a `theme` are version 1, from NeoSkript 0.1.0-beta.1, and are carried forward the same way, backed up as `config.yml.bak-v1`. Version 3 moved `variables.file` and `variables.storage` into the `databases` section, as the `default` database's `file` and `type`, backed up every 2 hours with the newest 12 kept. Every setting keeps its meaning, with two on purpose: `metrics: "false"` in quotes now turns bStats off, and a negative runtime error limit falls back to its default.

A file from a newer NeoSkript is never written.

<Aside type="note">
The update checker and bStats can both be turned off: see [updates and bStats](/docs/server/updates-and-metrics/).
</Aside>

## The full default config

```yaml title="plugins/NeoSkript/config.yml"
# NeoSkript's config. Docs: https://neoskript.dev/docs/configuration/
#
# Apply changes with /sk reload config. Most settings apply at once; those that say so wait for a
# restart. A bad value falls back to its default, with a warning in the console.

# Managed by NeoSkript, to carry your settings forward on updates. Don't edit it.
config-version: 3

# The look of NeoSkript's messages: /sk, reload reports and update notices. They use these as tags, so
# changing a colour here restyles them all. Write a style as MiniMessage tags: <gray>, <#FF4D9D>, or
# <gold><bold>. Script problems and runtime errors keep Skript's own look, which tools read.
theme:
  # <prefix> starts NeoSkript's messages, such as "<dark_gray>[<#FF4D9D>MyServer</#FF4D9D>]</dark_gray> ",
  # or blank for none.
  prefix: "<dark_gray>[<#FF4D9D>NeoSkript</#FF4D9D>]</dark_gray> "
  # The colour of message text that has no tag of its own.
  base: "<gray>"
  # <highlight>: names and values, such as a script or a number.
  highlight: "<#FF4D9D>"
```
