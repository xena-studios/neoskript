## Writing items

Items are written by name, with an amount in front if you want more than one: `diamond`, `3 iron ingots`, `a stone sword`, `64 oak logs`. The names are Minecraft's, from the server's registries, singular or plural.

```skript
command /kit:
	executable by: players
	cooldown: 1 hour
	trigger:
		give player 1 iron sword of sharpness 2
		give player 16 cooked beef
		give player an iron helmet named "<gray>Starter helmet"
		give player a diamond named "<aqua>Lucky gem" with lore "<gray>Found on day one"
		send "<green>Kit given." to player
```

- `of <enchantment> <level>` enchants it: `diamond pickaxe of efficiency 5`. The level is in digits; as in Skript, `efficiency V` isn't understood.
- `named "..."` sets its name, and `with lore "..."` its lore.

## Giving and taking

```skript
command /trade:
	executable by: players
	trigger:
		if player has 5 diamonds:
			remove 5 diamonds from player
			give player 1 netherite ingot
			send "Traded." to player
		else:
			send "<red>You need 5 diamonds." to player
```

`give X to player` and `give player X` are the same. `remove X from player` takes from their inventory. `drop X at location` drops it on the ground.

## The item in hand

`player's tool` is the item in the player's main hand. It's a slot, so it can be changed.

```skript
command /rename <text>:
	executable by: players
	trigger:
		if player's tool is air:
			send "<red>Hold an item." to player
			stop
		set name of player's tool to arg-1
		send "Renamed to %arg-1%." to player
```

## Inventories and slots

`player's inventory` is a player's inventory, `slot 0 of player's inventory` one slot of it, and `the helmet of player` an armour slot.

```skript
command /inv:
	executable by: players
	trigger:
		if player's inventory contains diamond:
			send "You have diamonds." to player
		set slot 0 of player's inventory to 5 golden apples
		set the helmet of player to a diamond helmet
		send "Amount in your hand: %item amount of player's tool%" to player

command /wipe <player>:
	permission: server.wipe
	trigger:
		clear arg-1's inventory
		send "Cleared %arg-1%'s inventory." to sender
```

## Items in variables

Items in global variables are saved, names, lore, enchantments and all, in the same format as Skript's `variables.csv`. An item put in a variable is a copy: changing the variable's item doesn't change the one it came from.

```skript
command /saveitem:
	executable by: players
	trigger:
		set {saved::%player's uuid%} to player's tool
		send "Saved %{saved::%player's uuid%}%." to player

command /loaditem:
	executable by: players
	trigger:
		give player {saved::%player's uuid%}
```

## Custom aliases

An alias is another name for items. Skript's default aliases add names like `speed potion`, `water bottle` and `flight 1 firework rocket`. A server can add its own in `.sk` files in `plugins/NeoSkript/aliases`, in Skript's format, which NeoSkript reads when it starts and on `/sk reload aliases`. Moving over from Skript copies `plugins/Skript/aliases`.

```skript nocheck title="plugins/NeoSkript/aliases/gems.sk"
gems:
	ruby¦s = minecraft:red_dye
	shiny gem¦s = minecraft:diamond {minecraft:custom_model_data={floats:[7f]}}
	[big] (rock|boulder)¦s = minecraft:cobblestone
	north anvil = minecraft:anvil[facing=north]
	gem¦s = ruby, shiny gem
woods:
	{woods}:
		oak = minecraft:oak_-
		birch = minecraft:birch_-
	{woods} plank thing¦s = -planks
```

- Aliases go in sections. Each line is `name = items`, where an item is a Minecraft id or another alias, and several are separated by commas.
- `¦` splits the singular from the plural: `ruby¦s` is `ruby` and `rubys`. `[big]` is optional, and `(rock|boulder)` is either.
- Components go in braces after the id, and block states in brackets. Placing a `north anvil` places it facing north.
- A `{name}:` section is a variation: `{woods} plank thing` is `oak plank thing` and `birch plank thing`, with `-` in the id filled in.
- `minecraft version = 1.20.5 or newer` at the top of a section loads it only on those versions.

They work as in Skript. An alias whose name is taken adds its items to that alias, and later files can use variations from earlier ones, Skript's defaults included. An item an alias file names is written with that name (`ruby`), and loses the name it has from its id: with the file above, `red dye` isn't an item, though `red_dye` still is. A line with a problem is reported with Skript's message and left out; the rest still load. The first 1,000 problems are listed, and the rest counted. [`aliases.load-defaults`](/docs/server/configuration/#aliases) turns Skript's defaults off.

For menus made of items, see [menus](/docs/scripts/menus/). Every item expression is in the [expressions reference](/syntax/expressions/).
